# API для согласования с backend

Документ подготовлен frontend-разработчиком. Предложения ниже НЕ означают,
что маршруты реализованы или согласованы. Секреты EKT остаются на сервере.

## Уже используется

- GET /api/search?q=... → {query, count, products: [...]}
- GET /api/products/{id} → {id, name, article, description, price, quantity,
  properties, stores, image, url}
- GET /api/cart → {items, total, items_count}
- POST /api/cart/add?product_id=515291&quantity=2 → снимок корзины.
  quantity здесь добавляемое количество, не итоговое.
- DELETE /api/cart/{id} и DELETE /api/cart присутствовали в проверенной схеме.

Виджет читает корзину перед подтверждением и показывает ее на отдельной вкладке.
Характеристики — значения properties, остаток — quantity; отсутствие остатка
не означает ноль. stores — массив {id, name, quantity}.

## Нужны ответы команды

1. Изменение количества: предлагается PATCH /api/cart/{id}?quantity=3
   с итоговым количеством и проверкой остатка. Уточнить метод и формат.
2. Сессии: сейчас корзина общая. Как передавать session_id для чата,
   корзины и вложений? Где создаётся сессия?
3. Чат: предлагается POST /api/chat/message с JSON:
   {"session_id":"uuid","message":"Подбери аналог","attachment_ids":[]}.
   Нужен пример ответа с текстом, товарами и аналогами с reason.
4. Вложения: предлагается POST /api/chat/attachment, multipart file +
   session_id → {"attachment_id":"..."}. Уточнить размер, типы и время обработки.
   На фронте пока JPEG, PDF, XLS/XLSX, DOC/DOCX, лимит 10 МБ.
5. Сертификаты: предоставить поле certificates: [{title, url}] либо иной
   согласованный формат. RECOMMEND не трактуется как список аналогов.
6. Checkout: вернуть cart_url/checkout_url, ведущий на актуальную корзину,
   и объяснить связь с сессией сайта EKT.
7. Ошибки: согласовать status/code/message, ошибки остатка и истечения сессии.
8. Подтверждение: backend должен проверять остаток и не добавлять товар
   по запросу AI до явного действия пользователя. Нужен idempotency key,
   чтобы повтор после потери ответа не добавлял товар второй раз.

## Примеры для передачи frontend

Пожалуйста, пришлите реальные обезличенные JSON-ответы: чат с товаром,
аналог с обоснованием, сертификат, успешная загрузка вложения,
нехватка остатка, корзина со ссылкой. Укажите URL работающего backend.

До получения контрактов AI, отправка вложений и переход на checkout
не считаются реализованными. Локальная сборка не заменяет проверку интеграции.
